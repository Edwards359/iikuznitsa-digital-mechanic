# Голосовое управление: отказ от API и дешёвые варианты

## Решение (2026-11-26)

На стенде **не используем** платный Yandex SpeechKit (`/api/voice`, непрерывные чанки с микрофона). В биллинге за день отладки SpeechKit **~322 ₽** при **~186 ₽** на YandexGPT — голос обошёлся дороже самого агента.

В продакшене по умолчанию `VOICE_STT_ENABLED` выключен. Пошаговый ремонт: **← →** (уже в UI).

Код `app/stt.py` и ffmpeg в Docker остаются для лабораторных включений (`VOICE_STT_ENABLED=1`), не для демо сдачи.

## Куда смотреть в будущем (без облачного STT на каждый чанк)

| Подход | Стоимость | Плюсы | Минусы |
| --- | --- | --- | --- |
| Клавиши / кнопки на экране | 0 | Надёжно, доступно | Не «hands-free» в перчатках |
| **Web Speech API** в браузере | 0 (у пользователя) | Без серверного счёчика | В РФ часто `network`, качество плавает |
| **Офлайн Vosk / whisper.cpp tiny** на VPS, только 5–10 фраз («следующий», «назад», «стоп») | CPU, без поминутного API | Фиксированный словарь = дёшево | Нужен бинарник, модель ~40–150 МБ |
| **Push-to-talk** одним нажатием, один запрос STT на команду | Копейки против цикла 3 с | Проще контролировать бюджет | Не hands-free |
| Локальное приложение (Android), системный STT | 0 для нас | Нормально на планшете в цеху | Отдельный клиент, не веб |
| Предзаписанные макро-кнопки («шаг +1») + TTS опционально | 0 | Демо для жюри | Не распознаёт произвольную речь |

Рекомендуемая линия для внедрения: **узкий словарь + офлайн-движок на сервере** или **PWA + Web Speech** с fallback на кнопки, без постоянного стриминга в SpeechKit.

## Если снова включать Yandex STT

- Только `VOICE_STT_ENABLED=1` и осознанный лимит (не цикл записи в фоне).
- Один сегмент на команду, длительность \< 5 с.
- Мониторинг SKU «Синхронное распознавание речи» в отчёте Cloud.
