# Описание продукта (черновик для кабинета, одна страница)

<!-- markdownlint-disable MD013 -->

**Название:** Цифровой механик — агентный помощник механика по акустическим проверкам двигателей.

**Задача хакатона:** автоматизировать разбор результатов акустической диагностики, поиск в руководствах по ремонту конкретного двигателя и подготовку заявки в ТОиР с подтверждением человеком.

## Что делает продукт

1. Получает результат ML-проверки (код неисправности, уверенность, признаки) и карточку машины.
2. Многошаговый агент (до `MAX_STEPS` шагов): поиск по индексу руководств, чтение страниц PDF, подбор запчастей из текста РК, формирование черновика заявки.
3. Ответ с цитатами (руководство, страница); превью страницы в интерфейсе.
4. Заявку в ТОиР отправляет только механик после явного подтверждения.

## Технологии

| Компонент | Реализация |
| --- | --- |
| Backend | Python 3.12, FastAPI |
| LLM | YandexGPT Pro (`LLM_PROVIDER=yandex`) на стенде |
| Поиск | Гибрид BM25 + BGE-M3 (RRF), CPU; опционально Tesseract OCR для сканов |
| Данные | 6 PDF руководств, 50 машин (CSV), журнал консультаций SQLite |
| Интеграции | REST к ML-сервису и ТОиР (OpenAPI заказчика) |
| Деплой | Docker Compose, HTTPS через Caddy |

Публичный репозиторий: `https://github.com/Edwards359/iikuznitsa-digital-mechanic`. Демо: `https://5.129.222.124:8080` (самоподписанный сертификат).

## Агентность

Инструменты: `get_vehicle`, `get_check`, `search_manual`, `read_pages`, `search_spare_parts`, `draft_ticket`, `submit_ticket` (только после подтверждения). Журнал шагов в UI и `data/journal.jsonl`.

## Экономика эксплуатации (ориентир по стенду, 26.11.2026)

- Диалог: YandexGPT — порядка **1,2 ₽ за 1000 токенов** (вход/выход по биллингу, см. `docs/cost-operation.md`).
- Embeddings и OCR: **локально**, токены LLM не тратятся.
- Голос на демо: **Web Speech API** (`VOICE_MODE=browser`), 0 ₽; SpeechKit опционально.

Пример накопления за день активных прогонов: **~175 ₽** LLM при ~146k токенов (журнал `consultations`).

## Эффект

Сокращение времени механика на поиск процедуры в PDF и оформление заявки; снижение риска ссылки на чужое руководство или выдуманный артикул за счёт проверки цитат и фильтра по двигателю.

## Готовность

Рабочий прототип на данных задачи: гибридный поиск, агент, UI, логирование, деплой. Видео-демонстрация — по сценарию `docs/VIDEO-SCRIPT.md`.
