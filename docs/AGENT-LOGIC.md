# Логика агента «Цифровой механик»

<!-- markdownlint-disable MD013 -->

Описание для GitHub и текста сдачи: что решает код, что — модель, какие ограничения жёстко прошиты.

## Роль

Агент `Consultant` (`app/agent.py`) обслуживает **одну выбранную машину** за запрос. Менять машину в ходе диалога нельзя. Модель видит системную инструкцию `SYSTEM` и набор `TOOLS`; цикл до `MAX_STEPS` (по умолчанию 8).

## Точки входа

| Вход | Поведение |
| --- | --- |
| `POST /api/consult` | Текст + `vehicle_id` + `session_id` + опциональный язык ответа |
| Правила до LLM | При `session_id` и статусе **normal** / **check_failed** / **bad quality** ответ собирается **без вызова LLM** (`_early_status`), журнал с `model: rules` |
| Голос | Только UI пошагового ремонта: Web Speech (`VOICE_MODE=browser`) или SpeechKit PTT; агент LLM не вызывается; кодовое слово «Помощник» |

После каждого consult запись в `consultations` и дополнение `journal.jsonl`.

## Инструменты (кто вызывает)

| Инструмент | Данные | Решение |
| --- | --- | --- |
| `get_vehicle` | Каталог JSON | Статика |
| `list_checks` | Сессии машины из JSON | Статика |
| `get_check` | HTTP → mock ML | Факт проверки |
| `explain_code` | `fault_types.json` | Статика |
| `search_manual` | `ManualSearch.search` | Гибрид BM25 + BGE-M3, фильтр по двигателю |
| `search_spare_parts` | тот же поиск + фильтр по шаблонам деталей | Гибрид + эвристика |
| `read_pages` | Индекс страниц + PNG | До 5 страниц одного документа |
| `ticket_history` | SQLite `tickets` | Локальная память заявок |
| `draft_ticket` | Валидация + `choose_urgency` | **Приоритет считает код**, не модель |
| *отправка заявки* | **Нет в TOOLS** | Только `confirm_draft` из UI |

Модель **не может** вызвать отправку в ТОиР.

## Ожидаемая цепочка при отклонении (промпт, не жёсткий граф)

1. `get_check` + сравнение с `list_checks` (динамика по прошлым сессиям — на усмотрении модели в тексте ответа).
2. `explain_code` при необходимости (коды F01…F14 **нет** в PDF).
3. `search_manual` → при обрыве процедуры `read_pages` на соседних страницах.
4. `search_spare_parts` по узлу/детали из процедуры.
5. `draft_ticket` с `operations`, `references` (документ + страница + цитата), `spare_parts`.
6. Механик подтверждает черновик → `confirm_draft` → mock ТОиР → `TKT-…`.

При **норме** черновик не создаётся (и правилами UI/агента запрещён смысл «ремонт срочно»).

## Проверки при `draft_ticket` (код)

- Проверка существует; ML-статус **anomaly**; качество не `bad`.
- Каждая ссылка: документ из `manuals.py` для этого двигателя; текст страницы загружается; если передана `quote` — подстрока должна быть на странице (`verify_citations` для ответа — аналогичная нормализация пробелов).
- `operations` не пустой; `conclusion` не пустой.
- `choose_urgency` (`app/priority.py`): пороги `anomaly_score`, повторяемость, `LOW_CONFIDENCE`, `forbids_operation`.

## Ответ механику (структура промпта)

1. Наблюдаемые признаки  
2. Вероятные причины и риск  
3. Что делаем по руководству (подготовка)  
4. **Ремонт по шагам** — нумерация, действие, ссылка «документ, стр. N»  
5. Черновик заявки (если уместен)

Интерфейс дополнительно строит `repair_steps` из ответа и payload черновика (`build_repair_steps`) для блока «Пошаговый ремонт» и превью PDF.

## Журнал и экономика

- На каждом шаге LLM в `steps[]`: инструмент, урезанный результат (до ~400 символов), токены и оценка `cost_usd` шага.
- В `journal.jsonl`: время, модель, провайдер, суммарные токены, список имён инструментов.
- Для Yandex на стенде в SQLite дублируется оценка `cost_rub` (см. `docs/cost-operation.md`).

## Язык

Первая строка user-сообщения задаёт язык ответа (`app/languages.py`); отдельные модели не подключаются.

## Что намеренно не делает агент

- Не ищет в руководствах **другого** двигателя (фильтр в RAG и в `read_pages`).
- Не придумывает цены и остатки запчастей (ТЗ).
- Не отправляет заявку без человека.
- Не обрабатывает OCR схем на страницах-картинках (только текстовый слой + PNG для глаз механика).
