## 1. Рекомендуемый сценарий (основной дубль)

Использовать **готовую проверку с отклонением** (после вашего прогона логика та же).

| Поле | Значение |
| --- | --- |
| Машина | **M333YK47** (МАЗ, гараж Г-102) |
| Двигатель | **ЯМЗ-236М2** |
| Проверка | **S-0005** |
| Код | **F08**, `signal_quality: good` |
| Метка в списке | «Проверка с отклонением · ЯМЗ-236М2» |

**Как выбрать в UI:** в списке машин найти `M333YK47` → в проверках `S-0005` → поле «Комментарий мастера» **пусто** → **«Разобрать проверку и вести по ремонту»**.

**Ожидание ответа:** 1–2 минуты возможны (YandexGPT на VPS). На записи можно **комментировать голосом**, что «ждём ответ агента», не отпуская кнопку записи.

### Порядок кадров (один дубль)

| Шаг | ~сек | Что делать | Что сказать (кратко) |
| --- | --- | --- | --- |
| 1 | 0–15 | Уже открыт UI, показать заголовок и **пороги** | «Цифровой механик для механика после акустики» |
| 2 | 15–30 | Выбор **M333YK47**, **S-0005**, клик «Разобрать…» | «Машина и проверка с отклонением» |
| 3 | 30–90 | Ждём; раскрыть **«Журнал шагов агента»** | «Агент сам ищет в РК этого двигателя» |
| 4 | 90–130 | Ответ, цитаты; прокрутить **«Страницы руководства»** | «Страница PDF в интерфейсе» |
| 5 | 130–160 | **Пошаговый ремонт**: 1–2 шага **«Следующий шаг»** / ← → | «Ведёт по шагам, не просит искать PDF» |
| 6 | 160–200 | **Черновик заявки** → сменить **приоритет** → **Подтвердить** | «Заявку отправляет только механик» |
| 7 | 200–240 | Прокрутить **карточку машины**: консультации, **преемственность**, токены | «История и стоимость» |
| 8 | 240–270 | *(если успеваете)* В комментарии: `регулировка зазора клапанов` → снова «Разобрать» **или** только показать баннер, если уже был | «Противоречие в РЭ и РК — обе формулировки» |
| 9 | 270–180 | Вкладка **GitHub** репозитория сдачи (README) | «Код открыт, PDF не в Git» |

Шаг 8 **опционален** — вырежите из дубля, если время поджимает.

| Машина | Проверка |
| --- | --- |

Только если остаётся время в 3 мин — иначе упомянуть в **описании продукта**.

---

## 4. Что вы делали в прогоне

В журнале на стенде часто фигурируют **P456AT178 / S-0003** — это **сбой записи** (`check_failed`), не лучший главный кадр для заявки. Для **полного цикла с черновиком** используйте **§1 (M333YK47 / S-0005)**.

---

## 5. OBS (кратко)

1. Сцена → Источник **«Захват окна»** → окно Chrome со стендом.
2. Выход: **MP4**, 1920×1080 или 1280×720, 30 fps.
3. Запись: **«Начать запись»** → выполнить §1 → **«Остановить»** → один файл.
4. Если дубль >3 мин — **новый полный дубль**, не нарезать.

**Ускорение ожидания LLM** (по правилам хакатона): только паузу ожидания, один итоговый файл, без склеек (например, ускорение в DaVinci/OBS export — по вашему усмотрению; при сомнении лучше **прогрев + голос в реальном времени**).

---

## 6. После записи

1. Залить файл на **Яндекс.Диск** (или другой хостинг): ссылка `https://`, **без авторизации** (проверка в инкогнито).
2. Вставить ссылку в поле **«Демо-видео»** в ЛК.
3. Убедиться, что в описании продукта совпадает с показанным (см. `docs/PRODUCT-SUBMISSION.md`).
