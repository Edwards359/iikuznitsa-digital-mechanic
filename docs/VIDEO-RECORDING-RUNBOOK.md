# Запись демо-видео: пошаговый бегунок

<!-- markdownlint-disable MD013 -->

Для владельца перед одним дублем. Правила: [кабинет, `Допы.txt`] — до **3 мин**, **один непрерывный фрагмент**, без склеек; можно **ускорить только ожидание LLM** в том же файле (если без нарезки).

**Стенд:** `https://5.129.222.124:8080`  
**Репозиторий:** `https://github.com/Edwards359/iikuznitsa-digital-mechanic`

| # | Действие |
| --- | --- |
| 1 | Открыть стенд в **Chrome/Edge**, принять сертификат, вкладка на весь экран или окно 1280×720+ |

## 1. Рекомендуемый сценарий (основной дубль)

Использовать **готовую проверку с отклонением** (после вашего прогона логика та же).

| Поле | Значение |
| --- | --- |
| Машина | **M333YK47** (МАЗ, гараж Г-102) |
| Двигатель | **ЯМЗ-236М2** |
| Проверка | **S-0005** |
| Код | **F08**, `signal_quality: good` |
| Метка в списке | «Проверка с отклонением · ЯМЗ-236М2» |

**Как выбрать в UI:** в списке машин найти `M333YK47` → в проверках `S-0005` → поле «Комментарий мастера» **пусто** → **«Разобрать проверку и вести по ремонту»**.

Либо быстрее: **«Демо-сценарий»** → пункт с **M333YK47 / S-0005** и ЯМЗ-236М2 (подставит машину и проверку).

**Ожидание ответа:** **1–3 минуты** на первом запросе после паузы — норма (YandexGPT, до 12 шагов агента, гибридный RAG). Вы писали, что «довольно долго» — это **ожидаемо**; на записи **не останавливайте OBS**, проговорите голосом, что агент ищет в PDF. После **прогрева** (§0) второй прогон часто **короче**.

### Клик за кликом (повторите на RECORD)

Нумерация — как в интерфейсе после обновления 27.11.

| # | Действие | Что должно появиться |
| --- | --- | --- |
| 1 | Открыть `https://5.129.222.124:8080`, принять сертификат | Страница «Цифровой механик» |
| 2 | Дождаться строки **health** в шапке | `yandexgpt/…`, фрагменты, **гибрид да**, 50 машин |
| 3 | Раскрыть **«Пороги и приоритеты»** | Заявка ≥ **0,50**; срочность; high / medium / low |
| 4 | **Демо-сценарий** → отклонение **M333YK47 / S-0005** *или* вручную те же поля | Двигатель **ЯМЗ-236М2**, код **F08** |
| 5 | **Комментарий мастера** — **оставить пустым** (как в прогоне) | Плейсхолдер «Пусто — агент разберёт…» |
| 6 | Нажать **«Разобрать проверку и вести по ремонту»** | Кнопка может «висеть»; спиннер / пустой ответ — ждём |
| 7 | Во время ожидания (**30 с – 3 мин**) смотреть **«Журнал шагов агента (отладка)»** (он открыт) | Цепочка вроде: `get_check` → `explain_code` → `list_checks` → `search_manual` → `read_pages` → … → `draft_ticket` |
| 8 | Когда придёт **«Ответ агента»** | Признаки F08, риск, цитаты «…» (документ, стр. N) |
| 9 | Прокрутить **«Страницы руководства»** (PNG) | Миниатюры PDF по найденным страницам |
| 10 | Блок **«Пошаговый ремонт»**: **«Следующий шаг»** 1–2 раза (или ← →) | Шаг N из M; в карточке машины обновится **преемственность** |
| 11 | **«Черновик заявки в ТОиР»** | JSON: `operations`, `references`, `urgency` |
| 12 | **Приоритет (механик может изменить)** — показать смену, например **medium** → **high** | Выпадающий список с расшифровкой |
| 13 | **«Подтвердить и отправить»** | Текст успеха: **TKT-00xx** (номер растёт при повторных прогонах) |
| 14 | **«Карточка машины»** → консультации, заявки, **преемственность ремонта**, токены/₽ | История и экономика |
| 15 | *(опционально, ~20 с)* В комментарии: `регулировка зазора клапанов` → снова «Разобрать…» | Жёлтый **баннер противоречия** РЭ/РК ЯМЗ-236 |
| 16 | Вкладка **GitHub** публичного репо (README) | Без ключей и без папки подготовки |

**Если черновика нет:** в журнале у `draft_ticket` часто «цитата не найдена» — повторите клик с тем же сценарием (на прогреве лучше дождаться черновика). Для записи надёжнее **прогрев с черновиком**, затем **новый дубль** с чистого шага 4 (или тот же прогон, если укладываетесь в 3 мин).

**Текст вопроса (не обязателен):** при пустом комментарии агент и так разбирает проверку. Если нужен повтор API-успеха:  
`Разбери отклонение. Найди страницы в руководстве, цитируй дословно фразу с read_pages, затем draft_ticket.`

## 5. OBS (кратко)

1. Сцена → Источник **«Захват окна»** → окно Chrome со стендом.
2. Выход: **MP4**, 1920×1080 или 1280×720, 30 fps.
3. Запись: **«Начать запись»** → выполнить §1 → **«Остановить»** → один файл.
4. Если дубль >3 мин — **новый полный дубль**, не нарезать.

**Ускорение ожидания LLM** (по правилам хакатона): только паузу ожидания, один итоговый файл, без склеек (например, ускорение в DaVinci/OBS export — по вашему усмотрению; при сомнении лучше **прогрев + голос в реальном времени**).

---

## 6. После записи

1. Залить файл на **Яндекс.Диск** (или другой хостинг): ссылка `https://`, **без авторизации** (проверка в инкогнито).
2. Вставить ссылку в поле **«Демо-видео»** в ЛК.
3. Убедиться, что в описании продукта совпадает с показанным (см. `docs/PRODUCT-SUBMISSION.md`).
